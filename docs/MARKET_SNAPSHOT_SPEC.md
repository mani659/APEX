# MarketSnapshot Specification

## 1. Mission

The `MarketSnapshot` represents the complete observable market state at exactly one simulation timestep. 

It is the ONLY market object visible to the Strategy layer (albeit indirectly via the `TradingContext`). The `TradingContext` derives its information from the `MarketSnapshot`, but never modifies it. 

---

## 2. Contents

The `MarketSnapshot` captures the precise physical state of an asset (or multiple assets) at a specific timestamp.

### Suggested Fields
- `timestamp`: The exact simulated time of the snapshot.
- `symbol`: The asset ticker (e.g., "XAUUSD").
- `OHLC`: The Open, High, Low, Close price array for the current timeframe.
- `volume`: Traded volume.
- `spread`: The current bid-ask spread.
- `bid`: The current best bid price.
- `ask`: The current best ask price.
- `tick_volume`: Number of ticks in the current bar.
- `session`: The active trading session (e.g., Asian, London, NY).
- `volatility_state`: Instantaneous volatility metric.
- `market_structure`: High-level regime identifier.
- `feature_snapshot_reference`: Cryptographic hash or ID to trace this exact snapshot in downstream logs.

---

## 3. Design Principles

### Immutability
A `MarketSnapshot` represents history. It is instantiated once per timestep and must be strictly immutable to ensure cryptographic reproducibility during simulation.

### Observable Information Only
It contains physical facts about the market (price, volume, time). It does **NOT** contain theoretical indicators, optimized parameters, or any subjective derivations.

### No Portfolio Information
A market tick does not know about the trader's account balance. Including portfolio data here breaks the separation of concerns. Portfolio data lives in the `TradingContext` and `PortfolioSnapshot`.

### No Research Conclusions
It must never include signals, predictions, or research labels (like "bullish_divergence"). Those are generated by the Strategy Engine or Research layer.

### No Trading Decisions
It contains no trading logic. It is purely descriptive state.

---

## 4. Future Extensibility

The `MarketSnapshot` is designed as a scalable state vector. It can be extended effortlessly without breaking the Strategy interfaces:
- **Tick Replay:** Instead of OHLC bars, the snapshot can contain sub-millisecond tick data.
- **Level II / Order Book:** Arrays for bids/asks at depth can be appended.
- **Options / Greeks:** Implied volatility surfaces and option chains can be included.
- **Multi-asset:** By converting the fields into HashMaps keyed by `symbol` (e.g., `prices["XAUUSD"]`), the snapshot supports simultaneous cross-asset evaluation perfectly, requiring no architectural redesign.
